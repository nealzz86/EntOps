这两项把已经做好的零散功能变成可交付的标准流程：体检负责「这台机器合不合要求」，功能搜索负责「知道去哪点」。

## 装机体检清单

左侧导航「装机体检」→ 点「开始体检」。工具只读取本机设置与共享目录可达性，**不修改任何配置**，逐项给出「合格 / 提醒 / 不合格 / 未知」四种结论，并在表格里写明实际读到的值。

体检项来自 `config\baseline.json`，按本单位基线自行增删：

```json
{
  "id": "computerName",
  "type": "computerNamePattern",
  "label": "计算机名符合命名规则",
  "group": "基础信息",
  "severity": "warn",
  "expect": "PC-",
  "hint": "计算机名应以 PC- 开头，便于资产系统对账。",
  "fix": { "button": "", "text": "" }
}
```

- `type` 决定这一项怎么判断（计算机名规则、加域、时区、电源计划、更新策略、Defender、第三方杀软残留、服务状态、必装软件、共享可达、系统盘余量、是否管理员运行）。
- `severity` 是 `fail` / `warn` / `info`，决定不合格时算「不合格」还是「需提醒」。
- `fix.button` 填 `config\routes.json` 里已有的按钮名，这一行就会出现修复按钮，点它等同于去原功能页点同一个按钮——确认提示、后台任务、进度条都照旧。**体检页自己不实现任何修复逻辑**，新增按钮名而不写处理函数只会得到一条告警。

读不到的项一律记为「未知」并说明原因，不会把探测失败伪装成「不合规」；共享目录无响应时整轮体检在后台继续，界面不会卡住。

## 功能搜索（Ctrl+K）

顶部栏的放大镜按钮或 **Ctrl+K** 打开面板，输入中文即可（例如「打印机」「清理」「ISO」）。

- **Enter** 执行第一项，**↑ / ↓** 选择，**Esc** 关闭；点某一行同样执行。
- 执行时先切到该功能所在页面，再触发对应按钮，所以看到的界面和结果与手动操作完全一致。
- 搜索结果来自 `config\commands.json`（按钮名 → 中文名称、分组、所在页面、关键字）。各页面是按需加载的，打开面板时那些控件还不存在，因此**没有渲染出来的界面无法被枚举**——新增加功能时要在 `commands.json` 补一条，否则搜不到。
- 全离线：面板只做本地字符串匹配，不联网、不读取任何凭据。
